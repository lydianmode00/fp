05. Git y GitHub

Git es un sistema de control de versiones distribuido. GitHub es una plataforma de hosting para proyectos Git. Antes de comenzar a trabajar con Git y GitHub, es importante entender los conceptos básicos de control de versiones y cómo utilizar estas herramientas para gestionar tu código de forma eficiente.

  • Proyecto: Conjunto de archivos y directorios que representan un trabajo de desarrollo.
  • Repositorio: Un proyecto que está siendo gestionado por Git. Contiene todos los archivos del proyecto y el historial de cambios.
  • Commit: Una instantánea del estado de los archivos en un momento dado. Cada commit tiene un identificador único y un mensaje descriptivo.
  • Branch: Una línea de desarrollo independiente dentro de un repositorio. Permite trabajar en nuevas características o correcciones de errores sin afectar la rama principal (main o master). Normalmente usaremos staging y development como ramas paralelas.
  • Merge: El proceso de combinar cambios desde una rama a otra. Se utiliza para integrar nuevas características o correcciones de errores en la rama principal. Nosotros haremos merges desde development a staging por cada tarea completada y desde staging a main al final de cada unidad.
  • Local: El espacio donde se almacenan los commits antes de ser enviados al repositorio remoto.
  • Remote: El repositorio alojado en un servidor remoto, como GitHub. Permite la colaboración entre varios desarrolladores y el acceso a los cambios desde diferentes ubicaciones. Subo cambios haciendo push a la rama remota, y los descargo haciendo pull.

01. Recorrido histórico del mundo web.

El paradigma de desarrollo en entornos servidor ha ido evolucionando con el tiempo, adaptándose a las necesidades cambiantes de los usuarios y las tecnologías disponibles. En cada época y contexto, los desarrolladores han tenido que adaptar sus enfoques y técnicas para satisfacer las demandas cambiantes del entorno tecnológico.

Para entender correctamente la evolución del desarrollo web en entornos servidor, es importante conocer la historia de la web y cómo ha cambiado a lo largo del tiempo. Desde los primeros días de la web estática hasta la era actual de aplicaciones web interactivas y dinámicas, cada etapa ha traído consigo nuevos desafíos y oportunidades para los desarrolladores.

Internet primigenio

En 1969, la red de ordenadores más grande del mundo se conocía como ARPANET, la precursora de internet. Era una red de comunicación muy limitada, principalmente utilizada por instituciones académicas y gubernamentales y fundamentalmente para fines académicos, de investigación y bélicos.

La web 1.0, la web estática

Podemos decir que Internet como lo conocemos hoy en día comenzó con la WWW en 1989.La web 1.0 se caracterizó por ser principalmente estática, con páginas web que ofrecían información de manera unidireccional. Los usuarios eran principalmente consumidores de contenido, y la interacción con las páginas web era limitada. Los desarrolladores se centraban en crear páginas web informativas y en la optimización de la velocidad de carga y la accesibilidad.

La web 2.0, la web dinámica

La web 2.0, termino acuñado en 2004, marcó un cambio significativo en la forma en que los usuarios interactuaban con la web. Surgieron plataformas de redes sociales, blogs y aplicaciones interactivas que permitían a los usuarios generar contenido y participar activamente en la web. Los desarrolladores comenzaron a centrarse en la experiencia del usuario, la interactividad y la personalización del contenido. Se popularizó el uso de tecnologías como AJAX, que permitían la actualización dinámica de contenido sin necesidad de recargar la página completa.

La web 3.0, la web semántica

La web 3.0, también conocida como la web semántica, se centra en la comprensión y el análisis de los datos para ofrecer experiencias más inteligentes y personalizadas. Se entiende que en la web 3.0 se deben integrar tecnologías como la inteligencia artificial, el aprendizaje automático y la realidad aumentada para crear experiencias más inmersivas y contextualmente relevantes. Los desarrolladores deberán adaptarse a estas nuevas tecnologías y enfoques para crear aplicaciones web más avanzadas y sofisticadas.

La web 4.0, la web natural

La web 4.0, también conocida como la web ubicua o la web de las cosas, se centra en la integración de la web con el mundo físico y la interconexión de dispositivos y objetos a través de Internet. Se espera que la web 4.0 permita una mayor automatización, personalización y conectividad en la vida cotidiana de los usuarios. Esta evolución de la web de momento es teórica, pero se teoriza que estará fuertemente marcada por la ausencia de interfaces de usuario tradicionales "GUI", y se apuntará más a interfaces naturales "NUI", donde el usuario interactúa directamente con los objetos y dispositivos a través de interfaces intuitivas y naturales como la interacción por voz con un asistente virtual.

02. Arquitectura cliente-servidor

La arquitectura cliente-servidor es un modelo de diseño de software que divide las responsabilidades entre dos componentes principales: el cliente y el servidor. El cliente es la parte de la aplicación que interactúa directamente con el usuario, mientras que el servidor es responsable de procesar las solicitudes del cliente y proporcionar los recursos necesarios. Esta arquitectura permite una mayor escalabilidad, flexibilidad y eficiencia en el desarrollo de aplicaciones web, ya que cada componente puede evolucionar de manera independiente y adaptarse a las necesidades cambiantes del entorno tecnológico.

Es fundamental entender que la verdadera fortaleza de esta arquitectura radica en los siguientes puntos:

  • Seguridad: Cuando desarrollamos aplicaciones en entornos servidor, la seguridad es una preocupación crítica. El servidor debe proteger los datos sensibles y garantizar que solo los usuarios autorizados puedan acceder a recursos específicos. Por esto, todas las operaciones y datos se manejan en el servidor, lo que permite una mejor protección de la información.
  • Escalabilidad: La arquitectura cliente-servidor permite una mejor escalabilidad, ya que el servidor puede manejar múltiples solicitudes simultáneamente y distribuir la carga de trabajo de manera eficiente mediante servicios de balanceo de carga como nginx. Esto facilita la expansión de la aplicación a medida que crece la demanda de usuarios y recursos.
  • Flexibilidad: La arquitectura cliente-servidor permite una mayor flexibilidad en el desarrollo y mantenimiento de aplicaciones web, ya que los componentes pueden evolucionar de manera independiente y adaptarse a las necesidades cambiantes del entorno tecnológico. Dividiremos entonces nuestros servicios en componentes relativamente independientes que puedan escalar por separado.

De esta forma, el cliente ejecutará su parte del código, normalmente JavaScript, relacionado con la presentación de la web, la navegación o aspectos poco relevantes como la pre-validación de un formulario (como mínimo, los formularios deben validarse siempre en el backend, pero podemos hacer una pre-validación en el frontend para que el usuario tenga un feedback inmediato). Del mismo modo el backend ejecutará el grueso del código, relacionado con la seguridad, la validación de operaciones, accesos a la base de datos y generación de contenido.

03. Tecnologías y lenguajes de programación

En el desarrollo web en entornos servidor, se utilizan diversas tecnologías y lenguajes de programación para crear aplicaciones web dinámicas y funcionales. Algunos de los lenguajes de programación más comunes incluyen PHP, Python, Ruby y JavaScript (Node.js). Cada lenguaje tiene sus propias características y ventajas, y los desarrolladores deben elegir el lenguaje más adecuado según los requisitos del proyecto y las preferencias del equipo de desarrollo. Además, se utilizan tecnologías como bases de datos, servidores web y frameworks para facilitar el desarrollo y la gestión de aplicaciones web en entornos servidor. Nosotros utiizaremos principalemte Python y su framework Django para el transcurso del módulo.

04. Diseño basado en dominios (DDD)

El diseño basado en dominios (DDD) es una aproximación al desarrollo de software que se centra en el dominio del problema y en la modelización de los conceptos del negocio. Esta técnica ayuda a crear aplicaciones más mantenibles y escalables, ya que se enfoca en la comprensión profunda del problema que se está resolviendo y en la creación de un modelo conceptual que refleje fielmente el dominio del negocio.

Al atacar el problema desde el dominio del negocio, se logra una mejor alineación entre la solución técnica y los requisitos del negocio, lo que resulta en aplicaciones más robustas y adaptables a los cambios en el entorno empresarial.

Vocabulary

  • Back-end: Part of an online product that runs in a server. To be considered a full back-end it should, at least: respond to requests (such as HTTP), change its behavior and store data in a permanent storage.
  • Web server: Software that responds to HTTP requests. It also runs in a server.
  • App server: Software that responds to HTTP requests and changes its behavior. It could be considered some kind of back-end.
  • Framework: Set of libraries with previously written code that streamlines the workflow.
  • HTTP: One of the many internet protocols that exist. It's a client/server text protocol with a very short lifespan.
  • Module: Piece of code that works independently and is able to communicate with other modules.
  • Interface: Piece of code that connects two different parts of an application.
  • Scalability: Property of an application that measures how easily can a project be expanded in size or in functionalities.
  • Flexibility: Property of an application that measures how easily can we modify an existing functionality.
