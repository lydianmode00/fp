01. Recorrido histórico del mundo web.

El paradigma de desarrollo en entornos servidor ha ido evolucionando con el tiempo, adaptándose a las necesidades cambiantes de los usuarios y las tecnologías disponibles. En cada época y contexto, los desarrolladores han tenido que adaptar sus enfoques y técnicas para satisfacer las demandas cambiantes del entorno tecnológico.

Para entender correctamente la evolución del desarrollo web en entornos servidor, es importante conocer la historia de la web y cómo ha cambiado a lo largo del tiempo. Desde los primeros días de la web estática hasta la era actual de aplicaciones web interactivas y dinámicas, cada etapa ha traído consigo nuevos desafíos y oportunidades para los desarrolladores.

Internet primigenio

En 1969, la red de ordenadores más grande del mundo se conocía como ARPANET, la precursora de internet. Era una red de comunicación muy limitada, principalmente utilizada por instituciones académicas y gubernamentales y fundamentalmente para fines académicos, de investigación y bélicos.

La web 1.0, la web estática

Podemos decir que Internet como lo conocemos hoy en día comenzó con la WWW en 1989.La web 1.0 se caracterizó por ser principalmente estática, con páginas web que ofrecían información de manera unidireccional. Los usuarios eran principalmente consumidores de contenido, y la interacción con las páginas web era limitada. Los desarrolladores se centraban en crear páginas web informativas y en la optimización de la velocidad de carga y la accesibilidad.

La web 2.0, la web dinámica

La web 2.0, termino acuñado en 2004, marcó un cambio significativo en la forma en que los usuarios interactuaban con la web. Surgieron plataformas de redes sociales, blogs y aplicaciones interactivas que permitían a los usuarios generar contenido y participar activamente en la web. Los desarrolladores comenzaron a centrarse en la experiencia del usuario, la interactividad y la personalización del contenido. Se popularizó el uso de tecnologías como AJAX, que permitían la actualización dinámica de contenido sin necesidad de recargar la página completa.

La web 3.0, la web semántica

La web 3.0, también conocida como la web semántica, se centra en la comprensión y el análisis de los datos para ofrecer experiencias más inteligentes y personalizadas. Se entiende que en la web 3.0 se deben integrar tecnologías como la inteligencia artificial, el aprendizaje automático y la realidad aumentada para crear experiencias más inmersivas y contextualmente relevantes. Los desarrolladores deberán adaptarse a estas nuevas tecnologías y enfoques para crear aplicaciones web más avanzadas y sofisticadas.

La web 4.0, la web natural

La web 4.0, también conocida como la web ubicua o la web de las cosas, se centra en la integración de la web con el mundo físico y la interconexión de dispositivos y objetos a través de Internet. Se espera que la web 4.0 permita una mayor automatización, personalización y conectividad en la vida cotidiana de los usuarios. Esta evolución de la web de momento es teórica, pero se teoriza que estará fuertemente marcada por la ausencia de interfaces de usuario tradicionales "GUI", y se apuntará más a interfaces naturales "NUI", donde el usuario interactúa directamente con los objetos y dispositivos a través de interfaces intuitivas y naturales como la interacción por voz con un asistente virtual.

01. ¿Qué es un lenguaje de marcas?

Entendemos por lenguaje de marcas cualquier sistema de codificación de información que use texto con etiquetas o anotaciones para definir la estructura, significado o presentación de un conjunto de datos. No son lenguajes de programación; normalmente no tienen lógica algorítmica, variables ni funciones aritméticas

HTML es un lenguaje de marcas porque utiliza etiquetas llamadas elementos con anotaciones llamadas atributos para describir la presentación que debe tener un texto. El resultado final de una presentación HTML depende siempre de la resolución final de la ventana en la que deba mostrarse.

  • Elemento: Componente de una página HTML. Se compone de una etiquetea de inicio, un contenido, y una etiqueta de fin.
    • La etiqueta de inicio se encuentra entre los signos "<" y ">" y describe el funcionamiento general del elemento. Por ejemplo <p> describe un párrafo y <h1> describe un encabezado de primer nivel
    • La etiqueta de cierre es exactamente igual que la de inicio, pero empieza con una barra. Por ejemplo: "%lt/h3> o "%lt/body>"
    • El contenido se encuentra entre las etiquetas de inicio y cierre y representa el texto

02. Elementos usuales

Los elementos HTML se escriben con etiquetas entre los signos < y >. Muchos tienen una etiqueta de apertura y otra de cierre; algunos, como <img> e <input>, no envuelven contenido. Los atributos aportan información adicional, por ejemplo href indica el destino de un enlace y alt describe una imagen.

Estructura básica de una página

<html> contiene el documento; dentro, <head> reúne información que no se muestra como contenido principal y <body> contiene lo que ve la persona que visita la página. Por ejemplo, <title> define el texto de la pestaña del navegador:

<!doctype html>
<html lang="es">
  <head>
    <meta charset="utf-8">
    <title>Mi primera página</title>
  </head>
  <body>
    <h1>Bienvenidos</h1>
    <p>Esta es mi página.</p>
  </body>
</html>

Títulos y párrafos

<h1> a <h6> organizan títulos por nivel, y <p> marca un párrafo. Se usan, por ejemplo, para presentar el título de una noticia y separar su contenido:

<h1>Noticias del centro</h1>
<h2>Jornada de puertas abiertas</h2>
<p>La jornada se celebrará el próximo viernes.</p>

Enlaces e imágenes

<a> crea un enlace; su atributo href indica a dónde lleva. <img> muestra una imagen: su atributo src indica el archivo y alt ofrece una descripción útil si no se puede ver la imagen o se usa un lector de pantalla.

<a href="https://www.example.com">Visitar el sitio</a>
<img src="logo.png" alt="Logotipo del centro">

Listas

<ul> crea una lista sin orden, <ol> una lista numerada y cada <li> representa un elemento. Por ejemplo, sirven para mostrar materiales o pasos:

<ul>
  <li>Cuaderno</li>
  <li>Bolígrafo</li>
</ul>

Secciones y contenedores

<header>, <nav>, <main>, <section>, <article> y <footer> describen partes de una página. Por ejemplo, <nav> agrupa enlaces de navegación y <main> identifica el contenido principal. <div> y <span> son contenedores genéricos cuando no hay un elemento más adecuado.

Tablas y formularios

Una tabla presenta datos relacionados en filas y columnas con <table>, <tr> (fila), <th> (encabezado) y <td> (celda). Los formularios recogen datos: <label> identifica un campo, <input> permite escribir y <button> permite realizar una acción.

<table>
    <th> <!-- Este es el encabezado, la primera línea de la tabla -->
        <td>Encabezado Columna 1</td>
        <td>Encabezado Columna 2</td>
    </th>
    <tr>
        <td>Fila 1 Columna 1</td>
        <td>Fila 1 Columna 2</td>
    </tr>
    <tr>
        <td>Fila 2 Columna 1</td>
        <td>Fila 2 Columna 2</td>
    </tr>
</table>
<label for="correo">Correo electrónico</label>
<input id="correo" type="email">
<button type="submit">Enviar</button>

03. Estilos

CSS permite cambiar la presentación visual de los elementos HTML. Para modificar un elemento concreto de forma rápida, se puede usar el atributo style en su etiqueta. Las propiedades se escriben como pares propiedad: valor y se separan con punto y coma:

<p style="color: navy; font-size: 18px;">
  Este párrafo tiene texto azul y más grande.
</p>

Si queremos separar el contenido de los estilos, podemos definir una hoja de estilos dentro de <head> mediante <style>.

<head>
  <style>
    p {
      color: darkred;
      background-color: lightyellow;
      padding: 10px;
      text-align: center;
    }
  </style>
</head>
<body>
  <p>Consulta el horario antes de salir.</p>
</body>

Entre las propiedades más comunes están color (color del texto), background-color (color de fondo), font-size (tamaño del texto), font-family (tipo de letra), text-align (alineación), margin (espacio exterior), padding (espacio interior), border (borde) y border-radius (redondea las esquinas). Para mantener los estilos ordenados y reutilizarlos en varios elementos, normalmente es preferible una hoja de estilos a escribir muchos atributos style.

Clases de estilos

El atributo global class permite asignar uno o varios nombres de clase a un elemento HTML. Por sí solo no cambia su aspecto: sirve para identificar elementos y aplicarles reglas CSS (también puede usarse desde JavaScript). En CSS, el selector de clase se escribe con un punto seguido del nombre; en el HTML, el valor de class se escribe sin ese punto:

/* En la hoja CSS */
.destacado {
  color: darkred;
  font-weight: bold;
}
<p class="destacado">Aviso importante</p>
<p class="destacado">Otro aviso con el mismo estilo</p>

La regla .destacado se aplica a todos los elementos cuya lista de clases incluya destacado. Por eso, una clase se puede reutilizar en muchos elementos, incluso de tipos distintos; no es un identificador único como id. El nombre de cada clase no lleva espacios: si se quieren asignar varias, se separan con espacios en el atributo.

<p class="destacado importante">Aviso destacado e importante</p>

Ese párrafo pertenece tanto a la clase destacado como a importante, así que puede recibir las reglas de .destacado y de .importante. Si una regla debe aplicarse únicamente a los elementos que tienen ambas clases a la vez, se combinan los selectores sin espacio: .destacado.importante. En cambio, un espacio entre selectores, como en .destacado .importante, selecciona un elemento de clase importante que esté dentro de otro elemento de clase destacado.

Cuando varias reglas aplicables definen la misma propiedad, el navegador resuelve el valor según la cascada y la especificidad del selector; normalmente, un selector de clase tiene más especificidad que uno de elemento, como p, pero menos que un selector de id. Por ello, conviene crear clases con nombres descriptivos y reutilizables, y enlazar la hoja CSS para separar los estilos del contenido HTML.

04. Hojas de estilo CSS

Una hoja de estilos externa es un archivo de texto con extensión .css. En él se escriben reglas CSS: un selector indica a qué elementos se aplican y, entre llaves, se declaran las propiedades y sus valores. Cada declaración termina en punto y coma:

body {
  font-family: Arial, sans-serif;
  background-color: #f4f4f4;
}

.destacado {
  color: darkred;
  font-weight: bold;
}

Guarda estas reglas, por ejemplo, en estilos.css. El selector body se aplica al elemento HTML <body>; .destacado selecciona los elementos cuya clase sea destacado (en CSS se escribe el punto, pero no en el atributo class).

Para utilizar la hoja, enlaza el archivo desde el <head> del documento HTML con <link>. La ruta de href debe apuntar a la ubicación del archivo CSS respecto al HTML:

<head>
  <link rel="stylesheet" href="estilos.css">
</head>
<body>
  <p class="destacado">Este texto tendrá el estilo destacado.</p>
</body>

Si ambos archivos están en la misma carpeta, basta con escribir el nombre del archivo en href. La misma hoja externa se puede enlazar desde varias páginas para compartir estilos y mantener el diseño separado del contenido.

Diseño de rejilla

display: grid convierte un elemento en un contenedor de rejilla: sus hijos directos pasan a ser elementos de la cuadrícula. Con grid-template-columns se definen las columnas y con gap el espacio entre celdas. Por ejemplo, esta regla crea tres columnas del mismo ancho:

.rejilla {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}

Aplica la clase al contenedor y coloca dentro los elementos que quieras organizar:

<div class="rejilla">
  <article>Elemento 1</article>
  <article>Elemento 2</article>
  <article>Elemento 3</article>
</div>

1fr representa una fracción del espacio disponible; por eso, las tres columnas comparten el ancho por igual. Grid también permite definir filas, separar elementos y adaptar el número o tamaño de las columnas a cada diseño.

Peticiones de medios

Las media queries aplican reglas CSS solo cuando se cumple una condición del dispositivo o de las preferencias de la persona usuaria. Se escriben con @media. Por ejemplo, podemos mostrar tres columnas en pantallas amplias y apilarlas en una sola columna cuando el ancho de la pantalla sea de 600 píxeles o menos:

.rejilla {
    grid-template-columns: 1fr 1fr 1fr;
  }

@media (max-width: 600px) {
  .rejilla {
    grid-template-columns: 1fr;
  }
}

El valor de corte debe elegirse según cuándo el contenido deje de caber cómodamente; no es necesario que corresponda a un modelo concreto de móvil. También se pueden usar media queries para respetar la preferencia de modo claro u oscuro configurada en el sistema.



body {
  background-color: #ffffff;
  color: #222222;
}

@media (prefers-color-scheme: dark) {
    body {
        background-color: #222222;
        color: #ffffff;
    }
}

En este ejemplo, los colores oscuros sustituyen a los claros cuando el navegador detecta que el sistema prefiere el modo oscuro; si no se cumple esa condición, se mantienen los valores iniciales.

05. IA integrada en el IDE

GitHub Copilot es un asistente de inteligencia artificial integrado en Visual Studio Code. Puede sugerir código mientras escribimos, explicar fragmentos y ayudar a modificar archivos. Úsalo como apoyo: sus respuestas pueden contener errores y siempre debes comprender y revisar el código que propone.

  1. Prepara VS Code e inicia sesión. Actualiza Visual Studio Code si es necesario, instala la extensión de GitHub Copilot si no lo está ya. El menú de chat con el agente se abre con CTRL+ALT+I, accede con una cuenta de GitHub que tenga acceso a Copilot. Sigue las instrucciones que aparezcan para habilitarlo.
  2. Abre un nuevo proyecto. En VS Code, abre la carpeta de la página web en la que vas a trabajar. Así podrás editar los archivos HTML y CSS y Copilot tendrá contexto del proyecto abierto.
  3. Prueba las sugerencias de código. Empieza a escribir HTML, CSS o un comentario que describa lo que quieres hacer. Copilot puede mostrar una sugerencia en texto tenue; pulsa Tab para aceptarla o continúa escribiendo para ignorarla. Revisa lo insertado antes de seguir.
  4. Pregunta desde el chat. Abre la vista Chat desde la barra lateral de VS Code y escribe una petición concreta. Por ejemplo: Explícame qué hace esta regla CSS y pon un ejemplo sencillo. Puedes seleccionar un fragmento de código y pedir una explicación, una corrección o una mejora.
  5. Describe bien la tarea. Indica qué archivo o elemento quieres cambiar, qué resultado esperas y qué límites debe respetar. Por ejemplo: En estilos.css, crea una rejilla de tarjetas que pase a dos columnas en pantallas estrechas. No cambies el HTML. Si la respuesta no es adecuada, aclara la petición en el chat.
  6. Revisa las propuestas de edición. Si utilizas un modo de agente que puede modificar archivos, inspecciona los cambios y el diff que muestra VS Code. Acepta solo lo que entiendas y necesites; rechaza o deshaz el resto. Antes de permitir acciones como ejecutar comandos, comprueba qué van a hacer.
  7. Comprueba el resultado. Guarda los archivos, abre la página en el navegador y verifica que se vea y funcione como esperas, también en móvil si procede. Corrige los errores y no entregues código que no hayas revisado y probado.

No compartas contraseñas, claves ni datos personales en tus peticiones. Sigue las normas de clase y recuerda que Copilot o cualquier otra IA ayudan a programar, pero no sustituyen tu criterio ni la comprensión del código.
